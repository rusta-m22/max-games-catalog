# Nonogram для VK Play — фактическая готовность

**Клиент 3.2.2 / подготовленный backend 3.2.4 · 20.10.2026**

Найден и исправлен конкретный блокирующий дефект: официальный ответ создания оплаты вернул HTTPS-ссылку на co.vkpay.ru, а обе наши проверки разрешали только vkplay.ru. Действующий сервер 3.2.3 записал безопасную диагностику в 11:45:51 UTC: scheme=https, host=co.vkpay.ru, port=default, userinfo=0. Публичная HTTPS-страница co.vkpay.ru имеет заголовок «VK Pay — Оплата» и реквизиты оператора; официальный сайт vkpay.ru перечисляет VK Play среди партнёров. Это проверка домена, а не успешная транзакция.

Новый настроенный клиент 3.2.2 готов к загрузке в Test. Фактическое открытие платёжной формы, успешный тестовый платёж и начисление VK Play **ещё не подтверждены**.

## Изменение

Добавлен только точный домен co.vkpay.ru вместе с прежним vkplay.ru:

- в исходный шаблон клиентской конфигурации и configure;
- в реально собранный Windows-клиент;
- в defaults VKPlay и серверных настроек версии 3.2.4.

Сохранены требования HTTPS, стандартного порта и отсутствия встроенных учётных данных. Похожие имена, co-vkpay.ru, co.vkpay.ru.evil.example и остальные поддомены vkpay.ru отклоняются. Платёжные параметры, включая вложенный URL, передаются без изменений в официальный mycomgames://demandbrowserform.

**Минимальное исправление действующего сервера 3.2.3:** VKPLAY_PAYMENT_HOSTS=vkplay.ru,co.vkpay.ru и перезапуск. Обновление серверного кода не обязательно. Явная переменная окружения имеет приоритет над defaults и после обновления до 3.2.4; её старое значение нельзя оставлять только vkplay.ru. Клиент 3.2.2 нужен в любом случае, поскольку native-мост также проверяет хост.

## Сохранённая игра и интеграция

Продолжен существующий проект rusta-m22/max-games-catalog, клиентская адаптация игры из site/games/nonograms. Сохранены 507 головоломок, 10 миров, цветные и большие поля, мега-картины, коллекции, подсказки, задания, рейтинг, анимации и RU/EN. Файлы сайта не изменялись. В этом исправлении игровые правила, прогресс, графика и экономика не менялись.

Клиент Windows 10/11 x64 использует Electron 44.7.0, изолированный renderer и сохранения с Windows DPAPI. Конфигурация итоговой поставки:

| Поле | Значение |
|---|---|
| backendUrl | https://nonogram-miami-rustamr22.mia0.amvera.tech/ |
| gcid | 0.2046788 |
| paymentHosts | vkplay.ru, co.vkpay.ru |
| releaseConfigured | true |
| GMRID | 50675 |

Используются документированные параметры запуска Game Center, GAS, billing/item/client, overlay demandbrowserform и подписанный GET callback. Секрет API хранится только на сервере. Начисление кошелька и учёт tid выполняются атомарно; клиент не может самостоятельно выдать покупные монеты. Дубликат callback не начисляет их повторно. Неоднозначный ответ не запускает автоматическую новую оплату.

Сохранено исправление 3.2.1: явная новая попытка повторяемого пакета сначала проверяет прежний заказ. Уже оплаченный заказ восстанавливается без нового checkout. Сбой сети/записи, обновление баланса, закрытие и перезапуск не создают платёж автоматически. Старый заказ остаётся для позднего callback. Одноразовый стартовый набор с неопределённым старым заказом пока требует сверки; для следующей проверки используется повторяемый пакет 1200.

## Кабинет и оставшиеся действия

Используется существующий nonogram-miami в Miami-0, одна реплика и постоянный /data. В кабинете ранее проверены тестовый платёжный режим и URL обратного вызова https://nonogram-miami-rustamr22.mia0.amvera.tech/api/vkplay/callback . Товары принятого каталога:

| itemdefid | Товар | Цена |
|---|---|---|
| 1001 | 500 монет | 49 ₽ |
| 1002 | 1200 монет | 99 ₽ |
| 1003 | 3000 монет | 199 ₽ |
| 1004 | 7000 монет | 399 ₽ |
| 1005 | Стартовый набор 800, один раз | 59 ₽ |

Изменить одну переменную Amvera и перезапустить; загрузить новый клиент в Test; проверить окно на повторяемом пакете. После открытия формы — выполнить официальную тестовую оплату, проверить настоящий callback, начисление один раз, отмену, отказ и сохранение после перезапуска. До этих результатов готовность к публичному выпуску не подтверждена. Возвраты/chargeback требуют отдельной сверки; автоматический refund не реализован.

Тестовый режим уже включён в кабинете, но актуальные тестовые реквизиты следует брать у площадки: в публичном примере документации указан прошлый срок действия карт. Реальная карта не нужна. Токены/пароли и полные подписанные платёжные URL не передаются в переписку.

Запись в Amvera в текущем сеансе заблокирована защитой браузера после безопасного входа. Изменение переменной и загрузка новой Test-сборки остаются ручными шагами. Автоматическое применение GitHub-коммитов в Amvera не подтверждено; публикация и Live требуют отдельного согласия владельца.
