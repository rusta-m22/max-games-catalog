# Nonogram для VK Play — фактическая готовность

**Клиент 3.2.3 · статус обновлён 21 октября 2026 года. Запуск Test build 6 подтверждён журналом пользователя; окно оплаты не появилось. Готовность к Live пока не подтверждена.**

Свежая проверка: [диагностика Game Center 21 октября](DIAGNOSTICS-2026-10-21.md). В last.xml отсутствует GAMINGFORMURL; штатная вкладка оплаты не настроена. Все 7 размеров и MD5 из манифеста совпали с артефактом 3.2.3, хотя метка дистрибутива — 3.2.5. Сам каталог на компьютере пользователя не прочитан. Успешное внедрение GCLay и работа панели оверлея не доказывают показ веб-формы.

Исправлен механизм открытия оплаты: клиент напрямую вызывает документированный GCLay DemandBrowserForm и проверяет наличие SDK, связь с Game Center и результат. Прежний успешный shell-вызов доказывал лишь передачу запроса, поэтому сообщение «Оплата открыта» было неточным. Теперь игра сообщает о переданном запросе и показывает отдельные ошибки SDK. Даже успешный возврат API ещё не является подтверждением видимой платёжной формы или платежа.

## Что сохранено

Использован существующий проект rusta-m22/max-games-catalog. Сохранены 507 головоломок и 10 миров, цветные и большие поля, мега-картины, коллекции, подсказки, задания, рейтинг, анимации и RU/EN. Исходный сайт, контент, графика, правила игры и серверная экономика в этом исправлении не менялись.

Windows 10/11 x64, Electron 44.7.0, изолированный renderer, сохранения через Windows DPAPI. Новый Node-API модуль собран для соответствующего Electron, использует packed x64 интерфейс официального заголовка. Настоящая DLL Game Center берётся только из документированного GC_GCLAY64_PATHNAME; в поставке её нет. Тестовая DLL также исключена из архива. Размеры формы оставлены нулевыми для стандартного расположения; реальный показ и HiDPI ещё проверяются отдельно.

В CI подтверждены переданные configure публичные параметры и успешная сборка. Точный HTTPS origin, отсутствие userinfo и нестандартного порта обязательны. Управляющие символы в URL отклоняются. Подписанный URL сохраняется без изменений. Секретов в клиенте нет.

Backend для этого исправления обновлять не нужно. Ранее наблюдался работающий backend 3.2.3 в Amvera Miami-0; подготовленный серверный архив 3.2.4 остаётся без изменений. Необходимая серверная настройка VKPLAY_PAYMENT_HOSTS=vkplay.ru,co.vkpay.ru сохраняется. В этом продолжении runtime Amvera не изменялся и его переменные не считывались.

## Оставшийся этап в кабинете

Конфигурация `-gup-/last.xml` проверена. Следующий шаг — [тест штатного веб-окна](OVERLAY-TEST-RU.md) с временным GAMINGFORMURL на главную страницу VK Play. Эта диагностика ещё не выполнена и не означает, что динамическая форма исправлена. Старый неопределённый заказ обрабатывается существующим диалогом; одноразовый стартовый набор пока требует отдельной сверки. Не переключать Live.

После появления формы выполнить только официальный тестовый платёж с актуальными тестовыми реквизитами площадки. Проверить настоящий callback, начисление один раз, отмену и отказ без начисления, отсутствие дубликата при повторном уведомлении и сохранение после перезапуска. Автоматические возвраты/chargeback не реализованы; они требуют отдельной сверки.

Callback существующего проекта: https://nonogram-miami-rustamr22.mia0.amvera.tech/api/vkplay/callback . Ранее пользователь подтвердил тестовый режим. В этом сеансе кабинет повторно не проверялся.
