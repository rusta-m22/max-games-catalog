# Nonogram для VK Play: фактическая готовность

**Клиент 3.2.1 / подготовленный backend 3.2.3 · 20 октября 2026 года**

Настроенная Windows-сборка готова к загрузке в **Test** и прошла запуск настоящего EXE на Windows. Публикация ещё не готова: настоящее платёжное окно и начисление VK Play не подтверждены. Текущий сбой установлен: действующий backend 3.2.2 отклоняет полученную ссылку с `payment_url_not_allowed`. Новая серверная диагностика позволит определить её домен и формат без раскрытия платёжных параметров.

## Что изменилось

- Клиент 3.2.1 устраняет бесконечную проверку одной зависшей попытки покупки. Для повторяемых пакетов доступна **явная** новая попытка после повторной проверки старого заказа. Уже оплаченный заказ восстанавливается без создания следующего.
- Закрытие диалога, обновление баланса, перезапуск, ошибка сети или записи сохранения не создают новую оплату. Старые серверные заказы остаются для позднего callback. Для одноразового стартового набора второй неопределённый заказ не создаётся; требуется подтверждение прежнего или сверка с площадкой.
- Backend 3.2.1 принимает сопоставление товаров без кавычек, удобное для Amvera. Backend 3.2.2 распознаёт документированные JSON-отказы HTTP 4xx, сохраняя неопределённость при тайм-ауте/ошибке шлюза.
- Backend 3.2.3 выводит только тип значения, протокол, домен, порт и наличие userinfo у отклонённой ссылки. Путь, query, fragment, пользователь и пароль не записываются. Проверка HTTPS и точного разрешённого хоста **не ослаблена**.
- Сохранено исправление IPC-сохранения из 3.2.0: ответ о записи возвращается один раз после завершения. Сохранены иконка EXE, сведения о продукте, изоляция renderer и Windows DPAPI.
- CI теперь собирает настроенный клиент с публичными параметрами существующего проекта после проверки preview EXE. Проверка прямого запуска настроенного EXE выполнена отдельно. Загрузка в Test остаётся отдельным действием; Live не меняется.

## Интеграция

Используются документированные параметры Game Center --sz_pers_id/--sz_token, серверная проверка GAS, billing/item/client, overlay mycomgames://demandbrowserform/0.2046788 и подписанный GET callback. Секрет API хранится только на backend. Клиент получает публичные адрес сервера и GCID. Начисление, кошелёк и учёт tid выполняются одной транзакцией SQLite; ответ клиента о закрытии/успехе окна не выдаёт монеты.

| itemdefid | Товар | Цена принятого каталога |
|---|---|---|
| 1001 | 500 монет | 49 ₽ |
| 1002 | 1200 монет | 99 ₽ |
| 1003 | 3000 монет | 199 ₽ |
| 1004 | 7000 монет | 399 ₽ |
| 1005 | Стартовый набор, 800 монет один раз | 59 ₽ |

Параметр VKPLAY_ITEMDEF_IDS должен содержать полное сопоставление этих пяти товаров. Включённый backend успешно стартовал со строгой проверкой формата; значения секретов не считывались и не публиковались. Реальная выдача монет по этим ID ещё не подтверждена. Возвраты/chargeback требуют сверки; автоматический refund не реализован.

Сервер работает в одном экземпляре с постоянным /data и SQLite. Отдельный VK Play Gateway не нужен и не создавался. Для Test подготовлен официальный bstool из GitHub Actions. В этом прогоне upload-test был **skipped**: новая 3.2.1 автоматически не загружалась. Секрет загрузчика вводится только в защищённое поле, не в переписку. Техническая возможность соединения bstool с площадкой без дополнительной настройки ещё не проверена.

## Что осталось вручную

1. В существующем Amvera nonogram-miami → **Code** заменить app.py и vkplay.py из обновления, затем выполнить сборку/запуск. Можно вместо двух файлов загрузить содержимое серверного архива в корень проекта. Должна появиться версия 3.2.3-vkplay-server. Существующие переменные, секрет и /data сохранить.
2. Загрузить весь каталог клиента 3.2.1 в **Test** официальным GameCenterUploader/bstool и обновить игру через Game Center. В корне каталога должен быть Nonogram.exe со всеми соседними файлами.
3. В магазине нажать повторяемый пакет, например 1200, и при диалоге — «Новая попытка». Проверить открытие формы и безопасную строку `payment_url_not_allowed ... scheme=... host=...` в логах Amvera. Полную платёжную ссылку и токены не пересылать.
4. После выяснения адреса и исправления допуска по официальному формату проверить overlay, успешный/отменённый тестовый платёж, фактический callback и начисление ровно один раз. Новая готовность к выпуску фиксируется только после этих проверок.

Самостоятельная запись в Amvera в текущем сеансе заблокирована защитой браузера после безопасного входа. Штатно продолжить этот защищённый сеанс инструмент не смог. Автоматическое применение GitHub-коммитов не подтверждено; предыдущие обновления пользователь применял вручную. Секреты повторно передавать не нужно.
