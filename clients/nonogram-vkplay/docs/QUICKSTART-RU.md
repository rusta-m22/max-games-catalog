# Nonogram 3.2.6: следующий тест в VK Play

[Скачать Windows ZIP 3.2.6](https://github.com/rusta-m22/max-games-catalog/actions/runs/39656134518/artifacts/12372007298). Фактически выполненные проверки: [отчёт 3.2.6](CHANGES-3.2.6.md).

1. Распакуйте архив **Nonogram-VKPlay-Windows-x64-3.2.6.zip** в новую папку. Не накладывайте его на старую сборку. Для загрузки выберите всю папку **Nonogram-VKPlay-win-x64**, где лежит `Nonogram.exe` и соседние файлы.
2. В официальном загрузчике загрузите её в **Test** существующей игры (GCID **0.2046788**), версия **3.2.6**. Не переносите в Live. Если скачивали GitHub artifact, внутри него находится ещё один ZIP — распакуйте и его.
3. Обновите игру в Игровом центре, запустите её оттуда и один раз нажмите «Открыть оплату VK Play» у пакета 1200 монет. Старый неопределённый заказ можно проверить через «Проверить баланс»; если он мешает, используйте явную «Новую попытку». Стартовый одноразовый набор пока не выбирайте.
4. Проверьте, появилась ли форма. Команда теперь использует `vkplay://demandbrowserform/`, как рекомендовала поддержка. Сообщение «Команда открытия оплаты отправлена» подтверждает только завершение системного вызова, а не появление окна или оплату.
5. Если формы нет, нажмите **Win+R**, вставьте `%APPDATA%\NonogramVKPlay\logs` и откройте `checkout.log`. Передайте этот файл и точное время попытки. Платёжные ссылки и токены в этот журнал не пишутся. Для поддержки также пригодится журнал Игрового центра за ту же попытку.

Amvera, товары, callback и настройки авторизации для этой сборки менять не нужно. Ранее применённую диагностическую настройку GAMINGFORMURL не меняйте одновременно с тестом клиента — так будет понятно, что именно повлияло на результат.

На этом этапе достаточно открыть и закрыть форму. Реальный платёж не нужен. Для следующего этапа следует отдельно подтвердить включение официальной тестовой платёжной системы; ветка Test сама по себе этого не гарантирует.
