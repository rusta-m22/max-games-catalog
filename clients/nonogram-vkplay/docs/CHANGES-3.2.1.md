# Nonogram VK Play — клиент 3.2.1 и backend 3.2.3

Повторное нажатие на покупку с неопределённым ответом прежде бесконечно проверяло тот же заказ. Теперь для повторяемых пакетов появляется диалог: проверить баланс, явно начать новую попытку или закрыть. Перед новой попыткой клиент проверяет старый requestId. Если заказ уже оплачен или ссылка известна, он восстанавливается без нового запроса в платформу. При ошибке связи/сохранения старый идентификатор не удаляется. Старый заказ остаётся на сервере для позднего callback. Для одноразового стартового набора новая неопределённая покупка не предлагается.

Ответ `UNEXPECTED_PAYMENT_HOST` сразу показывает тот же диалог. Начисление по ответу клиента по-прежнему невозможно: нужен подписанный callback на сервере. Повторный callback не начисляет монеты дважды.

Backend 3.2.3 дополняет журнал отказа ссылки безопасными полями: тип, протокол, домен, порт, наличие userinfo. Путь, параметры, fragment и данные входа не выводятся. Разрешённые хосты и проверка HTTPS не изменены. Для установления фактического домена нужно применить серверное обновление и получить новую тестовую ссылку от VK Play.

Проверки перед CI: 77 standalone Python-тестов; полный проект и браузерная проверка зафиксированы в evidence. VK Play и Native bridge в браузерной проверке имитируются. Настоящее открытие overlay, тестовая оплата и начисление площадки пока не проверены. Windows CI 39413852616 прошёл: реальный preview EXE, DPAPI, игра мышью, сохранения, RU/EN, затем guard настроенного EXE. Сам клиент в Test автоматически не загружался.

GitHub Actions теперь всегда применяет публичные параметры существующего проекта после Windows-проверки preview EXE и повторно проверяет guard настроенного EXE. Загрузка в Test остаётся отдельным ручным workflow input; Live не меняется.
