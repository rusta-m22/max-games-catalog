# 3.2.6 — открытие оплаты через Windows и vkplay:

21 октября 2026 года. Test, не Live. Версия 3.2.6 выбрана выше внутренней 3.2.3 и прежней метки дистрибутива 3.2.5, чтобы их больше не путать.

## Причина

Прямой `DemandBrowserForm` из основного процесса Electron не дал видимого окна у пользователя. 21.10 поддержка VK Play предложила использовать `ShellExecute` и схему `vkplay://demandbrowserform/`. Это основание для нового теста, а не доказанная причина сбоя старого SDK-вызова.

## Изменение

Кнопка → авторизованный сервер `/api/vkplay/order` → проверка точного HTTPS-хоста → `shell.openExternal(uri, {logUsage:true})` в основном процессе Electron. В используемой версии Electron 44.7.0 это Windows `ShellExecuteEx`, verb `open`, `SW_SHOWNORMAL`.

Формат команды:

```text
vkplay://demandbrowserform/0.2046788/?url=<encodeURIComponent исходной paymentUrl>&width=80%&height=80%&caption=Nonogram%20-%20VK%20Play
```

Исходный подписанный URL не нормализуется и не меняется; кодирование снимается один раз обработчиком Game Center. Размеры заданы в процентах по документации. В публичной странице пока используется старое имя схемы `mycomgames://`; именно `vkplay://` выбран по присланному владельцем ответу поддержки.

Нет `cmd.exe`, `start`, внешнего браузера или автоматического перебора способов открытия. Старый GCLay addon не вызывается и не попадает в сборку. Game Center управляет своим оверлеем самостоятельно.

Клиент ждёт завершения системного вызова. Ошибка Windows возвращает `PAYMENT_LAUNCH_FAILED`, чрезмерно длинная ссылка — `PAYMENT_URL_TOO_LONG` (документированное ограничение Electron/Windows: 2081 символ). Успешная отправка команды не обозначается как показ окна или подтверждение оплаты. Авторизация, серверные подписи, идемпотентность заказа и начисление по callback сохранены.

## Диагностика

`%APPDATA%\NonogramVKPlay\logs\checkout.log`: UTC-время, версия, событие `requested/submitted/failed/rejected`, метод, схема, GCID, имя платёжного хоста и фиксированный код ошибки. Полная платёжная ссылка, query, токены, UID и текст исключения не записываются. Журнал ограничен двумя файлами примерно по 128 КиБ. Ошибка записи не вызывает повторного запуска оплаты.

## Проверки

- Локально: 29 Node-тестов прошли (содержимое 507 уровней, URI, точное сохранение вложенных параметров, allowlist, отсутствие секретов в диагностике, ожидание Promise, отказ и повтор вызова).
- Python-сценарии, браузерные сценарии, Windows EXE и архив: результаты будут добавлены после CI.
- Новый Windows-тест вызывает настоящий `shell.openExternal` из упакованного EXE и проверяет полученный URI через временный локальный обработчик. Он отказывается заменять существующую регистрацию VK Play и удаляет тестовую регистрацию в finally. Это проверка системной передачи команды, не Game Center и не платёж.
- Реальный Game Center для 3.2.6, показ формы, sandbox-покупка, callback и начисление: **не проверены**.

Backend Amvera для этого исправления не изменяется. Публикация и реальные списания не выполняются.
