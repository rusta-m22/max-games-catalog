# Нонограммы — Мир пикселей · VK Play · 3.2.7

Существующая игра «Нонограммы — Мир пикселей», 507 головоломок и 10 миров, упакованная в Windows 10/11 x64 приложение Electron. Исходный каталог MAX/Яндекс не изменяется.

**Клиент 3.2.7, 23.10.2026:** исправлено название в интерфейсе RU/EN, заголовках игры и оплаты, стартовом экране и свойствах Windows EXE. Путь сохранений NonogramVKPlay, Nonogram.exe, конфигурация проекта и экономика сохранены. [Изменения 3.2.7](docs/CHANGES-3.2.7.md).

**Предыдущая сборка 3.2.6, 21.10.2026:** по рекомендации поддержки кнопка оплаты использует `vkplay://demandbrowserform/` через Electron `shell.openExternal` (Windows `ShellExecuteExW`). Прямой вызов GCLay убран из рабочего пути и DLL-мост не поставляется. [CI 39656134518](https://github.com/rusta-m22/max-games-catalog/actions/runs/39656134518) прошёл: 83 Python, 29 Node на Linux и Windows, 14 браузерных сценариев и настоящий Windows EXE с системным вызовом в локальный обработчик. [Скачать Windows ZIP](https://github.com/rusta-m22/max-games-catalog/actions/runs/39656134518/artifacts/12372007298), [подробные результаты](docs/CHANGES-3.2.6.md). 23.10.2026 владелец предоставил скриншоты открытых форм и статуса «Оплачено» на 99 ₽, баланс вырос с 155 до 1355 (+1200). По его подтверждению после перезапуска, обновления баланса и восстановления покупок осталось 1355 монет. Это пользовательская проверка 3.2.6; тип расчёта и серверные записи конкретной транзакции отдельно не проверялись.

Точный разрешённый домен `co.vkpay.ru` из 3.2.2 сохранён вместе с `vkplay.ru`. Backend для этого изменения обновлять не нужно. Его параметр `VKPLAY_PAYMENT_HOSTS=vkplay.ru,co.vkpay.ru` должен оставаться заданным. Секреты, кошелёк, подписи callback и защита от повторного начисления не меняются.

Сохранён диалог 3.2.1 для явной новой попытки повторяемого пакета с проверкой прежнего заказа. Поздние callback сохраняются, одноразовый стартовый набор не создаёт второй неопределённый платёж. Локальные тесты используют имитацию платформы. Windows CI проверяет настоящий preview EXE и guard настроенного EXE; он не выдаётся за проверку Game Center или платежей.

GitHub Actions автоматически применяет публичные параметры существующего Miami backend и GCID 0.2046788. Исходный config.json остаётся пустым шаблоном; для ручной сборки сначала configure. Секретов в клиенте нет.

- `game/` — сохранённая игра и графика.
- `desktop/` — изолированный IPC-мост, сохранения через Windows DPAPI и Game Center launch guard.
- `native/` — исторический эксперимент 3.2.3; в 3.2.6 не вызывается, не собирается и не включается в поставку.
- `server/` — GAS, подписанные callback, атомарный кошелёк SQLite, защита от повторного tid; самостоятельная поставка Amvera, только Miami-0.
- `tests/` — локальные контракты, browser-сценарии с имитацией площадки, отдельный реальный Windows EXE smoke test.
- `ci/nonogram-vkplay.yml` — копия workflow, устанавливаемая в корень репозитория `.github/workflows/nonogram-vkplay.yml`.

## Сборка и проверки

Node.js 24 и Python 3.12. Для запуска Windows-проверок нужен чистый Windows x64 runner без установленного обработчика `vkplay:`. Сборка 3.2.6 больше не компилирует нативный addon:

```sh
npm ci
npm test
npx playwright install chromium --only-shell
npm run test:ui
npm run build:win
python3 tools/package.py
```

На Windows вместо python3 можно использовать python. Настоящий Windows-прогон: `npm run test:native` после сборки. На Linux этот тест не объявляется пройденным.

Публичные параметры задаются через `npm run configure -- --backend https://YOUR-BACKEND/ --gcid 0.YOURID`, после чего нужно заново выполнить сборку. Секрет API остаётся только на сервере. `npm run upload:test` по умолчанию выполняет dry-run; `python3 tools/upload-test.py --execute` загружает настроенную сборку на Test при наличии защищённого VKPLAY_BUILD_TOKEN.

Итог: `dist/Nonogram-VKPlay-win-x64/` и `deliverables/Nonogram-VKPlay-Windows-x64-3.2.6.zip`. Распространять нужно весь каталог. Клиент не содержит механизмов реальных платежей вне VK Play. Game Center/overlay, реальные sandbox-транзакции и допуск на Live фиксируются отдельно в [протоколе проверки](docs/SANDBOX-CHECKLIST.md).
