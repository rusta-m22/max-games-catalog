# Сервер Nonogram для VK Play — 3.2.1

Готовая серверная поставка для отдельного проекта Amvera или Docker-хостинга. Python 3.11+, стандартная библиотека; дополнительных pip-пакетов нет. Сервис проверяет GAS, создаёт заказы, обрабатывает подписанные callback, хранит кошелёк и прогресс. Совместим с подготовленным клиентом 3.2.0.

**Обновление 20.10.2026:** сервер 3.2.1 добавляет формат `product=id` для формы Amvera без кавычек и сохраняет поддержку JSON. До обновления подтверждены HTTPS и готовность сервера 3.2.0 в существующем nonogram-miami (Miami-0); покупки отключены. Пользователь подтвердил запуск Windows-клиента из Test, а снимок кабинета подтвердил тестовый режим платёжной системы VK Play. Версию фактически развёрнутого сервера проверяйте через `/health`. Настоящая тестовая транзакция ещё не выполнена.

## Развёртывание на Amvera

1. Используйте существующий проект **nonogram-miami** в регионе **Miami-0**. Moscow не использовать. Содержимое папки из серверного архива загрузите в корень Code: `Dockerfile` и `amvera.yml` должны быть рядом с `app.py`. В полном архиве исходников нужные файлы лежат в `server/`.
2. Конфигурация уже задаёт HTTP-порт 8080 и постоянный каталог `/data`. Запускайте один экземпляр; обеспечьте HTTPS на внешнем адресе. Тариф в этой поставке не выбран.
3. Первый запуск возможен без ключей. `GET /health` возвращает HTTP 200 и `configured:false`; `GET /ready` — HTTP 503. Это режим ожидания настройки, без игровых сессий и платежей. База с фиктивными пользователями не создаётся. Для контроля живого процесса используйте `/health`; `/ready` нужен для контроля готовности игровых API.
4. Во вкладке переменных проекта задайте `VKPLAY_APP_ID` (GMRID); `VKPLAY_SECRET` добавьте именно как **секрет**. Оба значения должны быть установлены вместе. Не помещайте секрет в архив, репозиторий или клиент.
5. Настройте `TRUSTED_PROXY_IPS` по подтверждённым адресам/CIDR прокси Amvera. Не угадывайте диапазон. Пустое значение игнорирует X-Forwarded-For; адрес прокси вместо IPv4 игрока может привести к отказу GAS. Доверие ко всем адресам запрещено. Проверка реального IP обязательна перед тестом Game Center.
6. Перезапустите контейнер после изменения переменных. Проверьте `python settings.py --strict` и внешние `/health`, `/ready`. Успешный `/ready` подтверждает доступ к SQLite и наличие настроек, но не проверяет действительность ключа VK Play.
7. После настройки каталога и подтверждения тестового режима выполните раздел ниже. HTTPS-адрес сервера затем указывается в клиенте как `backendUrl`; пользователь самостоятельно выкладывает клиент в VK Play.

## Подключение без пофайловой загрузки

Подготовлена публичная серверная ветка `deploy/nonogram-vkplay-server` в репозитории `https://github.com/rusta-m22/max-games-catalog.git`. Dockerfile и amvera.yml в ней находятся в корне. В существующем проекте Amvera откройте «Репозиторий» → «Подключить GitHub, GitLab, Bitbucket», укажите URL и эту ветку. Токен для чтения публичного GitHub не требуется. Серверная версия — 3.2.1, автоматически с main не синхронизируется. Сборка и runtime платные; подтверждённый тариф проекта — 0,40 ₽/час, 290 ₽/30 дней.

## Подключение платежей

GMRID сервера и GCID клиента должны относиться к одному проекту. Создайте пять товаров в VK Play с согласованными ценами и задайте `VKPLAY_ITEMDEF_IDS` с настоящими ID. Форма Amvera может запрещать кавычки и в обычных переменных, и в секретах; используйте формат без кавычек. Ниже только пример структуры, **2001–2005 не являются подтверждёнными ID вашего проекта**:

```text
coins_500=2001,coins_1200=2002,coins_3000=2003,coins_7000=2004,starter=2005
```

Прежний формат JSON также поддерживается:

```json
{"coins_500":"2001","coins_1200":"2002","coins_3000":"2003","coins_7000":"2004","starter":"2005"}
```

`catalog.json` задаёт количество монет: 500, 1200, 3000, 7000, starter 800. Черновые ID из этого файла перекрываются переменной. Включить биллинг без полного корректного сопоставления нельзя. Проверка формата не подтверждает наличие товаров в VK Play.

Оба формата требуют ровно пять известных товаров и пять уникальных положительных ID. Повторяющиеся ключи, неполный список и некорректные ID отклоняются. Вывод ошибки не содержит введённое значение. Для формата без кавычек тип «секрет» не требуется; API-ключ `VKPLAY_SECRET` по-прежнему хранится как секрет.

Укажите callback `https://<backend>/api/vkplay/callback` в кабинете. Отдельно включите тестовую платёжку и подтвердите её состояние. Только после этого разрешите создание заказов: `VKPLAY_BILLING_ENABLED=true` и перезапустите. Этот флаг **не включает sandbox** и не переключает площадку между тестовыми и реальными деньгами. Перед публикацией выполните `SANDBOX-CHECKLIST.md` из серверного архива или `docs/SANDBOX-CHECKLIST.md` из полного архива.

## Проверка сервера

Из распакованного серверного архива:

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 smoke_check.py https://ВАШ-ДОМЕН --expect waiting
python3 smoke_check.py https://ВАШ-ДОМЕН --expect ready
```

`waiting` используется до добавления ключей; `ready` — после. Проверка делает только чтение `/health`, `/ready` и запрос кошелька без авторизации (ожидается отказ). Никаких списаний или имитации успешного платежа на рабочем сервере нет. Локальные платёжные тесты используют отдельную временную SQLite и FakeTransport, не VK Play.

Запуск только для локальной проверки, без Docker:

```bash
BIND_ADDRESS=127.0.0.1 DATA_DIR=./data python3 app.py
```

Пример для Docker-хостинга, режим ожидания настройки:

```bash
docker build -t nonogram-vkplay-server:3.2.1 .
docker run -d --name nonogram-vkplay-server --restart unless-stopped --stop-timeout 45 -p 127.0.0.1:8080:8080 -v nonogram-vkplay-data:/data nonogram-vkplay-server:3.2.1
```

Внешний HTTPS обеспечивает прокси хостинга. Файл `.env.example` — справочник без секретов; Python сам его не загружает. Для обычного Docker параметры можно передать через `--env-file`, для Amvera — через переменные и секреты кабинета.

## Хранение и восстановление

Постоянный каталог обязателен. Один экземпляр backend на SQLite; для нескольких экземпляров нужна общая транзакционная БД. При остановке SIGTERM сервис завершает текущие запросы и закрывает SQLite. Лимит — 32 одновременных соединения по умолчанию; лишние получают HTTP 503. Это не результат нагрузочного теста.

```bash
python3 backup.py /data/backups/nonogram-2026-10-14.sqlite3
```

Команда создаёт согласованную копию через SQLite Backup API, проверяет целостность и не перезаписывает существующие файлы. Базу в WAL-режиме нельзя надёжно копировать одним обычным `cp` во время работы. Регулярное расписание и копии вне хостинга должны быть настроены после развёртывания; сейчас они не настроены.

Для восстановления остановите приложение, сохраните текущий каталог данных, поместите проверенную копию под именем `vkplay.sqlite3` в **новый пустой** постоянный каталог и подключите его как DATA_DIR. Не подмешивайте старые `-wal`/`-shm`. Запустите один экземпляр и проверьте `/ready`, кошелёк и заказы. Восстановление более ранней копии может потерять платежи, поступившие после неё: перед возвратом продаж нужна сверка с площадкой. Локальный тест подтверждает восстановление баланса, прогресса, сессии и защиту от повторной доставки сохранённого платежа.

## Обработка операций

OTP записывается как хеш до единственного вызова GAS; после неясного результата требуется новый запуск через Game Center. Сессионные токены в БД хешируются, живут 12 часов. Кошелёк и права хранятся на сервере; произвольный локальный баланс не импортируется.

Callback получает сырой набор параметров GET и проверяет подпись по документации VK Play. Заказ привязан к uid и товару. Начисление, ledger и запись tid совершаются одной SQLite-транзакцией. Повторная доставка того же tid отвечает `status=ok` без повторного начисления. Значение sum информационное: выдаётся количество монет из сохранённого заказа. После тайм-аута создания заказа статус `unknown` не даёт монет; поздний корректный callback может завершить заказ. Однозначный отказ API переводит заказ в `failed` и разрешает новую попытку. Оплаченный заказ восстанавливается даже при отсутствии полученного URL оплаты. Закрытие окна не считается подтверждённой отменой: без подписанного callback начисления нет.

Данные `/data/vkplay.sqlite3`, WAL, synchronous=FULL. Журналы платежей: vk_orders, vk_transactions, ledger. Не включайте query string callback, заголовки авторизации и тела запросов в журналы прокси. В режиме ожидания настройки callback получает `errcode=0` (повторить позже), а не подтверждение начисления.

Платёжные URL разрешены только для точных хостов в allowlist. Если реальная площадка возвращает иной официальный хост, сначала подтвердите его, затем добавьте на сервере и в клиенте. Не использовать `*`.

Перед выпуском нужны тесты реального merchant_param, callback, GAS и платёжного URL. Автоматические возвраты/chargeback и администраторское разрешение зависших unknown-заказов не реализованы. Античит рейтинга требует отдельного аудита. Тесты в `tests/` используют имитацию VK Play и в Docker-образ не входят.
