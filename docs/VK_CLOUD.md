# Размещение в VK Cloud

Пакет готовится для вашего проекта VK Cloud. Доступ к консоли из браузера ChatGPT заблокирован политикой среды; состояние проекта, ресурсы, права и тарифы не проверены. Поэтому ниже — воспроизводимая конфигурация для существующего Linux-сервера, без создания новых платных ресурсов.

## На уже имеющемся сервере с Docker Compose

Нужны публичный домен, направленный DNS-записью A/AAAA на сервер, и входящие TCP 80/443. UDP 443 нужен только для HTTP/3. Docker и Compose должны быть установлены по официальной инструкции: https://docs.docker.com/engine/install/ . Не открывайте лишние административные порты.

1. Распакуйте архив на сервере в отдельную папку проекта. Не кладите его внутрь каталога другого действующего сайта.
2. Скопируйте `deploy/env.example` в `deploy/.env`, замените `games.example.com` своим доменом без протокола. Если 80/443 уже заняты существующим веб-сервером, интегрируйте `site/` в него вместо запуска второго сервера на этих портах.
3. Для общего адреса рекламного модуля выполните из корня пакета (либо внесите moduleBase вручную в ads-config.js):

```sh
node scripts/configure-origin.mjs https://ВАШ-ДОМЕН
```

4. Проверьте конфигурацию и запустите контейнер:

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml config
docker compose --env-file deploy/.env -f deploy/compose.yaml run --rm web caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d
```

Caddy обслуживает только `site/`, выпускает и обновляет TLS-сертификат при корректном DNS и доступных портах. Файлы сайта подключены в режиме чтения. Данные сертификатов хранятся в Docker volume. Проверить журнал:

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml logs --tail=80 web
```

Остановка сохраняет сертификаты:

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml down
```

Папку `site/` можно обновлять без пересборки контейнера. Перед обновлением сохраните копию действующих файлов. Модуль рекламы выпускайте в новую версионную папку, затем меняйте manifest.json — порядок описан в ADS_MODULE.md.

## Если используете статический хостинг, объектное хранилище или существующий CDN

Загрузите содержимое `site/` с сохранением путей. Настройте HTTPS, главный документ `index.html`, JavaScript MIME `text/javascript`, WebAssembly MIME `application/wasm`, выдачу `.pck` как двоичного файла. Большие файлы Godot и озвучки не исключайте из загрузки. Для `shared/ads/*` настройте CORS, для манифеста и кода — проверку актуальности кеша. Не перенаправляйте запросы отсутствующих `.js`/`.wasm` на HTML главной страницы.

Публикуйте только `site/`, не весь проект: исходные тесты, служебные файлы и будущий `.env` не должны раздаваться веб-сервером. Учётных данных в пакете нет.

## Подключение в MAX

После проверки HTTPS-адреса добавьте его как адрес мини-приложения к вашему боту в кабинете MAX. Документация: https://dev.max.ru/docs/webapps/introduction . Кнопку запуска можно назвать «Играть». Подключение выполненного сайта к боту требует прав в кабинете MAX; в этой передаче оно не делалось.

Каталог использует официальный скрипт https://st.max.ru/js/max-web-app.js и кнопку «Назад». Игра работает и при недоступности моста. Данные запуска не используются как доказательство личности пользователя, серверной авторизации и платежей здесь нет. Реклама для MAX отключена независимо от рекламной конфигурации.

## Перед открытием игрокам

- Откройте каталог по HTTPS на телефоне и компьютере, проверьте поиск и все 18 карточек.
- Проверьте две 3D-игры и запуск БУМбилы, полноэкранный режим, звук и возврат в каталог.
- Проверьте сохранение прогресса после перезагрузки и паузу при сворачивании.
- Откройте через MAX, проверьте кнопку «Назад» и отсутствие показов рекламы.
- Отдельно на рекламных площадках проверьте отмену и успешный просмотр rewarded: ровно одна награда только при подтверждении.

Точный тариф и размер нового сервера выбираются после просмотра существующих ресурсов и оценки нагрузки. Эта инструкция не является заказом платных услуг.

Источники конфигурации: https://caddyserver.com/docs/automatic-https , https://caddyserver.com/docs/caddyfile/directives/file_server , https://caddyserver.com/docs/caddyfile/directives/header , https://github.com/docker-library/docs/blob/master/caddy/README.md .
